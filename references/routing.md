# 定序决策（routing）

路线 = 目的排序 × 书类型 × 章节依赖。先识别类型，再套策略，最后按依赖微调。

## v1 已启用类型

### C 教程 / 体系文档（依赖序强）

按依赖序重排，通用节奏：**概念弹药 → 范式/原理 → 动手实践 → 纵深收口**。

- 目的 C（求职）：概念 → 原理 → 低代码/动手 → 面试题 + 作品。
- 目的 B（原理）：目录序全读，重机制轻动手。
- 目的 D（解决问题）：从目标案例倒推，用到哪读到哪。
- 目的 E（系统掌握）：严格目录序 + 每章练习。
- 目的 A（兴趣）：挑有趣章节，允许跳读。

### B 在线方法论 / 长文（章节相对独立）

按目的直读相关部分：

- D（解决问题）：先读直接相关章节，再补前置。
- B（原理）：概念依赖序。
- C（求职/考试）：高频考点章节优先 + 真题驱动。
- E（系统掌握）：通读 + 每章小结。

## v1 暂缓（占位）

- A 叙事类（小说/传记）：定序价值低 → 顺序读或按兴趣切口跳读。
- D 案例集/手册：无强顺序 → 问题驱动索引跳读。

## 依赖分析要点

- 从 README/目录提取章节顺序与自述依赖（如"每部分是下一阶段阶梯"）。
- 识别可跳读章节（综述、番外、环境配置）与必读章节（核心概念、范式）。
- 社区精选/附加章节：按目的选挂（如面试题汇总挂到求职周）。
- 输出路线时必须带一句依据说明（依赖关系 + 目的），并声明"这是我的重构建议，非官方读法"。

## 路线示例（Hello-Agents，目的 C>B=D，每日 15 分钟）

第 1 周概念（1→3→2 章）→ 第 2 周范式与协议（4→10 章读原理）→ 第 3 周低代码动手（第 5 章 + Dify 教程）→ 第 4 周纵深 + 面试题（8→13 章 + 面试题一页纸）。
